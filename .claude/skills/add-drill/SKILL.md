# add-drill

ドリル1つ = `src/content/docs/drills/<カテゴリ>/<ID>.md` 1ファイル。本文は書かず、frontmatter の `drill:` に中身を書く。ページの表示は `src/components/DrillDetail.astro`、図は `src/components/Court.astro` が frontmatter から組み立てる。

## 手順

1. **元の情報を読む**：依頼のメニュー文やメモを読む。練習会のメニューを集めた `menus-raw/`（ローカルにだけある。なければ飛ばす）と、洗い出し一覧 `menus-raw/drill-inventory.md` があれば、同じドリルがないか、どのIDを使う予定かを確かめる。
2. **ドリルの単位を決める**（下の「ドリルの分け方」）。既存のドリルの派生形で済むなら、新しいファイルは作らない。
3. **カテゴリとIDを決める**（下の「カテゴリとID」）。同じカテゴリの最大の番号の次を使う。
4. **ファイルを書く**（下の「frontmatter の書き方」「図の書き方」）。書き方に迷ったら、近いカテゴリの既存ドリルを1つ読んで合わせる。
5. **文章を確認する**：yomiyasu スキルが使えるなら、`node scripts/extract-prose.mjs <カテゴリ/ID>` で文章を抜き出して yomiyasu にかけ、直した内容をファイルに戻す。使えないときは、短い主語や句のあとの読点（「球出し役は、」）を外す程度にとどめる。
6. **ビルドと表示を確認する**（下の「確認」）。
7. **共有のプレビュー画像を作る**（プッシュの前に毎回）：`npm run og` を動かす。描く側のコード（`Court.astro` など）を変えたときは、全部の画像が作り直しになる。古い画像・ない画像だけを作り直し（`public/og/<ID>.png`）、`public/og/manifest.json` の指紋を更新するので、両方をコミットする。古いかどうかは、画像の材料（ドリル名・カテゴリ・練習の目的・図のデータと、描く側のコード）の指紋で見分ける。`npm run og -- --check` は一覧を出すだけ。CI では作らない。描く手は決まり（`src/lib/og.ts`）で選ぶので、できた画像を開いて決めの場面が伝わるかを見る。球を2つ以上同時に使う手は、その手だけを描く（決まりの4）。合わないときだけ図のデータに `ogSteps: [番号, …]` を書く。
8. **推測で書いたところを書き手に伝える**：元の情報に書かれていなかった配置、球出しの位置、ラリーの有無、ポイントなどは、どれを推測したかを一覧にして確認してもらう。

## 書き手の指摘は規則にする

書き手の指摘（「ここが跳ぶ」「この動きが違う」など）は、言われた1か所だけを直して終わりにしない。

図の描き方を決めている共通のファイルは `src/scripts/court-anim.ts`・`src/lib/side-figure.ts`・`src/lib/side-render.ts`・`src/lib/side-blend.ts`・`src/lib/swing-path.ts`・`src/lib/arm-ik.ts`・`src/lib/og.ts`・`src/config/court.ts`・`src/components/Court.astro`・`src/components/CourtFrame.astro`・`src/components/DiagramLegend.astro`・`src/content.config.ts`。直しの多くがここに集まるので、2つの作業で同時に直さない（ぶつかって、互いの直しを壊す）。ほかのドリルにも同じことが起きていないかを探し、なるべく規則にして、コード（`src/content.config.ts`、`src/components/Court.astro`、`src/scripts/court-anim.ts`、`src/lib/og.ts`、`src/config/court.ts`）か、このスキルに書く。図のデータに座標や個別の調整を書き足すのは、規則にできないときだけにする。

書き手の注文が今ある規則（コード、このスキル、`docs/`）のどれにも当てはまらないときは、作業を始める前に「これはどういう規則ですか」と書き手に聞き、規則として言葉にしてもらう。聞くときは、私が考えた規則の案を添える（例: 「キッチンの中から投げる球出しは、いつも上から投げ下ろす弧にする、という規則でよいですか」）。決まった規則はコードかこのスキルに書く。書き手が「この場だけ」と決めたときだけ、例外としてそのドリルのデータに書き、理由を `docs/decisions.md` に残す。決めたことは `docs/decisions.md` に、図の決まりは `docs/diagrams.md` に残す。

## ドリルの分け方

- **派生形（`variants`）にするのは、打ち方だけが違うもの**：フォア/バック/ランダム、スライス/ロール、ノーバウンド/ワンバウンド、ボールの高さ（足首・腰下・高め）など。
- 派生形があるドリルでは、図（アニメーション）をどの派生形で描いたかを `default: true` でちょうど1つに付ける（付け忘れはビルドのエラーになる）。
- 派生形に図（`diagram`）を書くと、ドリルのページの一番上の図の上に派生形の切り替えボタンが出て、押すと図・球出しの文（派生形の `feed`）が切り替わる。図のない派生形は本体の図を使う。図のある派生形が1つもなければ、切り替えボタンは出ない（書き手と決めた 2026-11-28）。
- 派生形の `name` は短い名前（フォア、バック、スライスなど）、`note` は「フォアでドロップ」のように「〇〇で（打つ球）」の形で書く。練習中に「今回：フォア　フォアでドロップ」と出るため。
- **配置・球出しの位置・ラリーの有無・ゲームのルールが違えば、別のドリル**にする。例：半面とクロス（全面）は別ドリル。7/11 の始め方の違いも別ドリル。
- 同じ練習の言い換え（「ストローク→ドロップ」と「ドライブ→ドロップ」など）は1つにまとめる。
- ドリル名はチームの呼び方をそのまま使う（トラン、7/11、ボレスト、スキニーシングル、ファイヤーファイトなど）。一般的な言い方に直さない。

## カテゴリとID

IDは「英数字3文字のカテゴリ + 3桁の数字」（例: `dnk001`）。カテゴリは `src/config/categories.ts` が正。

| コード | カテゴリ | 入れるもの |
|---|---|---|
| `dnk` | ディンク | ストレート/クロスのディンク、攻め/守りのディンク |
| `drp` | ドロップ | トランやベースラインからのドロップ、3rdショットドロップ |
| `rst` | リセット | 近くでのリセット、トランでのリセット、リセットラリー |
| `spd` | スピードアップ・ファイヤーファイト | スピードアップ、カウンター、ファイヤーファイト |
| `vly` | ボレー | ボレスト、ボレーボレー、ブロックボレー、攻撃的ボレー |
| `vdk` | ボレーディンク | ディンクやドロップを弾ませずに、ボレーディンクで柔らかく返す（4th の受け方など） |
| `4th` | 4thショット | 相手の3rdを受ける4th（受け流す・ロール・フリック・ブロック） |
| `trn` | トランジション | 前に詰める（アプローチ）、サーブ側 vs リターン側の勝負 |
| `lob` | ロブ・スマッシュ | スマッシュ、ロブへの対応 |
| `drv` | ストローク | ストロークのフォーム、ドライブ |
| `rtn` | リターン | サーブを受けて打つリターン |
| `ftw` | フットワーク | サイドステップなど |
| `gam` | ゲーム形式 | ディンクゲーム、7/11、スキニーシングル、キャット&マウス |

**サブカテゴリ**：メインのカテゴリ（`category`、IDの頭・フォルダ・サイドバーの場所）は1つだけ。ほかのカテゴリの練習にもなるときは、`subCategories: [rst, vly]` のように、サブカテゴリをいくつでも書く（書き手と決めた）。練習役が実際に打つ球・する動きで選ぶ（球出し役や相手役の球では選ばない。ただし相手役も同じ練習をするラリーは入れる）。ロブに下がる、斜め後ろへ下がって打つなど、動きそのものが練習になるものは `ftw`。メインと同じカテゴリは書かない（ビルドが止まる）。ラリーかどうかはカテゴリにせず、`rally` の印で見せる。サブカテゴリはドリルのページの印、ビルダーのカテゴリの絞り込み、ドリル一覧（`/drills/`）の「ほかのカテゴリのドリル」に出る。サイドバーには出さない。

**表示順**：IDは作った順の番号、表示順（サイドバーやドリル一覧で並ぶ順）は別に持つ。すべてのドリルに frontmatter の最上位で `sidebar: { order: 番号 }` を書く（カテゴリの中で 1, 2, 3…）。新しいドリルを途中に並べたいときは、IDは最大の番号の次を使い、表示順だけを入れたい位置にして、後ろのドリルの表示順を1つずつずらす。

「アップ」はカテゴリにしない（ストレートディンクなどは `dnk` に入れる）。一度使ったIDはなるべく変えない（メニューのURLで使うため）。ただし今（2026-11 時点）は試行錯誤の段階なので、書き手の指示があれば付け替えてよい。

## frontmatter の書き方

型は `src/content.config.ts` が正。最小の例：

```yaml
---
title: トランからストレートドロップ
description: トランから相手のキッチンに落ちるドロップをストレートに打つ
sidebar:
  order: 1
drill:
  id: drp001
  category: drp
  scene: サーブ側がベースラインからトランまで上がってきて、キッチンまであと一歩のところにいる。
  purpose: 確実にドロップを相手のキッチンに落とし、スマッシュや強めの球を打ち返されないままキッチンへ上がる。
  setup: 2人1組でストレート（正面）に向かい合う。球出し役はキッチンライン付近、練習役はトランに立つ。1面で2組同時にできる。
  feed: 球出し役がキッチンから練習役のトランへ球を出す。
  steps:
    - 練習役はトランで構えて待つ
    - 来た球をストレートにドロップし、相手のキッチンに落とす
    - 一定時間で球出し役と練習役を交代する
  points:
    - ネットの少し上を通し、相手のキッチンに落とす
  diagram:
    fence: far-left
    players:
      - { id: A, at: far-left-kitchen, role: feed }
      - { id: B, at: near-left-tran, role: practice }
    shots:
      - { from: A, to: B, type: dink, feed: true, n: 1 }
      - { from: B, to: fence.inside, type: drop, n: 2 }
  variants:
    - { key: fh, name: フォア, default: true, note: フォアでドロップ }
    - { key: bh, name: バック, note: バックでドロップ }
  builderDefault: { min: 2, sets: 5 }
---
```

- `purpose`（目的）と `points`（練習のコツ、最大5つ）は、練習中にスマホで見る項目。短く、具体的に書く。`setup`（人数・配置）、`feed`（球出し）、`steps`（やり方）は「練習方法の詳細」に入り、アニメーションを補う。
- 図の下には、見出し「想定する試合の場面」（`scene`）、「その場面でやりたいこと」（`purpose`）、「練習の目的」（`focus`）、「練習のコツ」（`points`）の順で出る。前の2つが試合の話、あとの2つがこの練習の話。練習中にいちばん意識してほしいことなので、どちらも1〜2文で短く書く。
  - `scene`: このドリルが想定する試合の場面。何が起きていて、何が困るかを書く。例（4th003）: 「サーブ側がトランから3rdのクロスドロップを打ち、キッチンへ上がろうとしている。」
  - `purpose`: その場面でこの球を打つと何が起きるか（何のためにやるか）を、言い切りで書く。例（4th003）: 「4thで浮かせずに早いタイミングで返し、相手がキッチンへ上がる時間を与えず、5thで攻めさせない。」
  - 試合に近い形のドリルと、その要素だけを取り出して簡単にしたドリルがある。簡単にしたドリルも最終的には同じ試合の場面のための練習なので、`scene` と `purpose` の大きな目的は、試合に近い形のドリルと同じにする（例: 4th001〜4th006 はすべて 4th005 と同じ）。そのうえで `focus`（重点）に、そのドリルで特に取り組むことを1文で書く（どのドリルにも書く）。
  - **ディンクの高さの書き方**：ディンク・ボレーディンク・ドロップ・リセットなど柔らかく落とす球の文では、「ネットぎりぎり」「ネットの低いところを通す」と書かない（ぎりぎりをねらうとネットにかけやすい）。「相手が打つところで高くない（相手にノーバウンドで強く打たれない）」ことが大事だと書く（書き手が決めた規則）。ディンクの打ち合いでやりたいことは「相手が浮かせるのを待つ」ではなく、「コース・深さ・速さを変えて相手を揺さぶり、ミスや浮いた球を誘う」と書く（待っているだけでは相手の球は浮かない。書き手の指摘）。図も同じで、ディンクの仲間とリセットはコードが打つ人の側で山を作り、ネットの上を余裕を持って越えてから下げる（`SOFT_ARC`）。
- ディンクのドリルは、攻めの場面（揺さぶって浮いた球を攻める）と守りの場面（押されている中でミスせずしのぐ）で、`scene`・`purpose` を分ける（書き手と決めた 2026-11-28）。守りが中心のドリル（dnk002・dnk009）は守りの文、それ以外（攻める側と守る側の両方がある dnk010 も含む）は攻めの文を使う。
- 「キッチンへ上がると相手と対等になる」のような、どのドリルにも共通する前提は書かない（「大原則」ページ `src/content/docs/principles.md` にまとめる）。
- 最初から見せるのは図・`scene`・`purpose`・`focus`・`points` だけ。`setup`・`feed`・`steps`・`variants`・`notes`（補足）は「練習方法の詳細」のトグルに入る。`links`（関連リンク）は「関連リンク」のトグルに入り、0件でもトグルを出して「なし」と書く。ID・カテゴリ・`aliases`・`builderDefault` はページに出さない。
- `links`（関連リンク）には、そのドリルの元になった動画や投稿を `{ title: 名前, url: URL }` で書く。公開されているものだけを載せ、練習会の団体名や参加者が分かる投稿は載せない。分からなければ書かない（空のままでよい）。
- 文体は「〜する」の常体。役割は「球出し役」「練習役」「相手役」、人は図と同じ A・B で呼ぶ。
- `builderDefault` は、ビルダーでこのドリルを足したときの初期値（分×セット）。ドリルのページには出ない。その日の時間はメニューのURLが持つ。元のメニューに書かれた「1セットの分数 × セット数」があればそれを使う。

## 図の書き方

座標はフィート。コートは縦向きで x: 0〜20（左→右）、y: 0〜44（上のベースライン→下のベースライン）。ネットは y=22、キッチンラインは y=15 と y=29。**下側が自分たちの側（練習役の側）**。

- **立ち位置は名前で書く**：`at: 手前/奥-左/右-深さ`（例: `near-right-baseline`）。座標はコード（`src/config/court.ts` の `LANES`・`DEPTHS`）が決める。数字を直接書かない。
  - 手前 `near` = 下側の自分たち、奥 `far` = 上側の相手。左 `left`・右 `right` は図で見た左右のレーン。サイドライン寄り（ほぼ端）は `leftSide`・`rightSide`、少し端に寄った位置は `leftOuter`・`rightOuter`、レーンの真ん中から少しセンターライン寄りは `leftInner`・`rightInner`、センターライン寄りは `leftCenter`・`rightCenter`（半面で斜めに打ち合うときなど）。
  - 深さ: `kitchen`（キッチンライン付近）、`tran`（トラン = キッチンラインとベースラインの中間）、`baseline`（ベースラインの後ろ。サーブ・リターン・3rdショットを打つ位置）。
  - 名前に当てはまらない位置（半面の練習など）だけ `x`・`y` を書く。移動先（`type: move` の `to`）にも同じ名前を使える。
  - トランは位置（線）の考え方で、エリアとして塗らない。
- **ドロップの的（柵）**：ドロップ系の練習は、相手のキッチンに柵をL字に置き、柵に当てずに柵の内側へ落とす。`fence: far-left` のように「手前/奥-左/右」で書くと、サイドラインから40cm・キッチンラインからパドル1本分の位置をコードが計算する（`FENCE`）。着地点は `to: fence.inside`（柵の内側）、クロスドロップは柵の角をねらうので `to: fence.corner`。
- **コートの使い方**：ストレートは同じ x（例: 5 と 5）、クロスは対角（例: 5 と 15）。半面は左半分（x: 0〜10）の中に置き、`zones: [left]` で示す。
- **人**：`role` は `feed`（球出し役）/ `practice`（練習役）/ `partner`（味方）/ `opponent`（相手）。全員右利きとして自動で腕とパドルを描く。構えを変えるときだけ `paddle: fh | bh` を付ける。
- **打球**：`type` は `dink` `rollDink`（ロールディンク: 順回転をかけるディンク。ディンクの仲間でいちばん速く、鋭いクロスを狙う） `sliceDink`（スライスディンク: 面を少し上へ開いたまま短く前へ運ぶ。上から下へは切らない） `shortHop`（ショートホップ: 弾んだ直後のすねの高さの球を、ひざを深く曲げて体の前で取り、手首を固めたまま短く運ぶ。受ける球は、受ける人のすぐ手前で弾む） `drop`（腰より下の球だけ。腰より上の `hit` を書くと図を作るときに止まる） `reset` `drive` `speedup` `lob` `smash` `serve` `return` とボレーの4種類、人の動きは `move`。ボレーは `volleyDink`（ボレーディンク: ネットより下で当てて、弧を描いてポトッと落とす。ディンクやドロップをノーバウンドで受けるとき）、`block`（ブロックボレー: 速い球を、パドルを立てた面で止めて返す。腰より低い球には使わない。低い球はリセットにする。図を作るときに確かめていて、腰より低い `hit` を書くと止まる）、`roll`（ロールボレー: 回転をかけて沈める）、`punch`（パンチボレー: 上から足元へ打ち込む。ファイヤーファイトの打ち合い）から選ぶ。来た球をパドルで受けて勢いを殺してから打つ（トラップ）ときは、`dinkTrap`（ディンク（トラップ）: 足元でワンバウンドさせてからディンク）、`sliceDinkTrap`（スライスディンク（トラップ））、`resetTrap`（リセット（トラップ）: 弾ませずに、ポンと上げた球をリセット）、`volleyTrap`（ボレー（トラップ）: 弾ませずに、ポンと上げた球をボレーディンク）を使う。トラップの動きはコードが付けるので `afterBounce` は書かない。トラップのあいだは図に「トラップ」と自動で出る。ディンクのトラップでは、来た球は手前で一度弾んでから受ける（`bounce: front` を書く）。トラップしてからもう一度弾むので、試合では反則だが、練習の形として書き手と決めた。リセットを打つ人は自動でバックハンドの構えになり、スピードアップやカウンターを受けて打つリセットは、`hit` を書かなければ腰の高さになる。線の形・太さ・アニメーションの速さは種類で自動で決まる（線はまっすぐ）（`src/config/court.ts`、「図の見方」ページ）。
- **球出しの球は、練習する打ち方に合わせる**：派生形で打ち方を変えるドリルは、球出しの球も打ち方に合わせて変え、`feed`（派生形ごとの `feed` も）に、どんな球を出すかを具体的に書く（例: ロールはゆっくりで少し高めに弾む打ちやすい球、スライス・ショートホップは少し攻めるような速めで低い足元への球）。図では、球出しの線の名前（「球出し（ゆっくり・高め）」など）と山の高さ（`peak`）で違いを見せる（書き手と決めた 2026-11-28）。
- **球出しは球種ではない**：球出しの球は、出す球の種類を `type` に書き、`feed: true` を付ける（名前は「球出し（ディンク）」になる）。
- **順番 `n`**：打つ順に 1, 2, 3… と付ける。番号ごとに1コマになり、アニメーションで1手ずつ再生される。同じ番号の線は同時に動く。
- **人が動く**：`{ from: B, to: 位置の名前, type: move, n: 2 }` で動かすと、次の手からは動いた先に描かれる。動いた先から打つ線も `from: B` と書く（コードが動いた先のパドルから出す。座標を書くとパドルから外れて、ボールが跳んで見える）。
- **相手に向かう球**は `to` に人のID（パドルに向かう）、**コートに落とす球**は `to` に座標を書く。
- `curve` は書かない（上から見た図の線はまっすぐ）。`label` は名前を変えたいときだけ。同じ手に同じ名前の線が2本以上あるとき（球を2つ以上同時に使うドリル）は、コードが名前を最初の1本にだけ付けるので、`label: ""` で消さなくてよい。球を2つ以上同時に使う手の並べ方も気にしなくてよい（前の手のボールの続きになる球を、コードが先に並べる）。
- **バウンド**：アニメーションでは、バウンドした位置に黄色い輪が出る（横から見た帯でも同じ瞬間に出る）。位置はコードの決まりで決まるので、座標は書かない。
  - `to` が座標・位置の名前の球（コートに落とす球）は、終点で弾む。途中で人が取る（ノーバウンド）なら `bounce: false`。
  - サーブ・リターンは、受ける人の手前で自動で弾む。
  - それ以外で相手に向かう球（`to` が人）はノーバウンド。弾んでから打つ球（ディンクの打ち合い、トランやベースラインへの球出しなど）は `bounce: front`（受ける人の手前で弾む。ベースラインの後ろで受けるなら深め）。
  - 深さは `kitchen`・`tran`・`baseline` のほか、キッチンラインから少し下がった `kitchenBack`、キッチンラインとトランの間 `kitchenTran`（スマッシュの落とし先など）、キッチンの中の落とし先 `inKitchen`（ボレーディンクやディンクを相手のキッチンに落とすとき。例: `far-leftSide-inKitchen`）、キッチンの中のネット際 `netSide`（ショートホップなどの短いディンクの落とし先）がある。
  - **ラリー**：題名と説明の文には「ラリー」「ラリー無し」を書かない（ページとサイドバーとメニューを作るページに、`rally` から「ラリー」「ラリーなし」の印が自動で出る。書き手と決めた）。全部のドリルの図に、ラリー形式かどうかを `rally` で必ず書く（書かないとビルドが止まる。書き手と決めた規則）。ラリーでない（1本ずつ球出しして返す、決まった順に打つ）なら `rally: false`。ラリーで、手を書いたとおりに描いて最後の手から最初の手へ続けて繰り返すもの（球が4つ、点数を数える、途中でディンクをはさむなど）は `rally: true`。最後の手で球が最初の手を打つ人へ届くように書く（例: spd001 はリセットのあとディンクを3本はさむ）。ラリーを続けるドリルで1往復を繰り返すものは、図に `rally: 2`（往復の回数）を書き、打球は1往復ぶん（例: A→B と B→A）だけ書く。コードが、球出し（手元で一度弾ませて出す）から始めて2往復させ、繰り返すときは新しい球の球出しから始め直す。球出しの `afterBounce` は書かない（コードが付ける）。`afterBounce` を書くのはトラップのときだけ（dnk011）。
  - **ロブに下がる人**：ロブ（`bounce: front`）に下がる人の `move` は、横から見た図で、後ろを向いて走り、着く少し前に前足を踏み込んで前を向き直る（コードが自動で付ける。書くことはない）。弾む前に打つ（スマッシュ・ボレー）ときは、ロブに `bounce` を書かないので、ボールのほうを向いたまま下がる。
  - **基本の位置と受ける位置**：基本の位置で待ち、相手が打ったら横（や斜め後ろ）に動いて受け、打ちながら基本の位置へ戻る人は、人に `sidestep: 受ける位置` を書く（`at` が基本の位置）。動き（move）はコードが足すので書かない。例: `{ id: B, at: near-rightInner-kitchen, sidestep: near-rightOuter-kitchen, role: practice }`。ラリーで2人とも動くときは2人とも書く。最初の手で自分から打つ人は、受けたあとの位置から始まり、繰り返しても跳ばない（4th001〜004・006、dnk003・006〜010）。
  - それ以外の動き（ロブで下がる、前に詰めるなど）は、`{ from: B, to: 位置の名前, type: move, n: 番号 }` で書く。打たれた球に合わせて動くなら、その打球と同じ番号にする（反応の遅れはコードが付ける）。人の動きには「移動」の名前を付けない（矢印だけ）。
  - 受ける人の手前に落として矢印を着地点で止めたいときは `to: A.front`（A の手前のキッチン側に落ちる）。
  - 決まりに当てはまらないときだけ `bounce: [x, y]` で書く。
  - 打つ前に一度弾ませてから打つ球（ワンバウンドさせてから出す球出しなど）は、その打球に `afterBounce: true` を書く。手から落としたボール（トラップして上げたボール）がパドルの真下で弾み、打点まで上がってから打球が始まる。
- **ゲーム形式の点**：2人で1つの点を動かすゲーム（綱引きクロスディンクゲーム gam001 など）は、図に `score: { to: 勝ちの点, plus: 点が増える人, minus: 点が減る人 }` を書き（点が増える側＝目盛りの右・+ は手前の人 B、減る側は奥の人 A）、決まる球に `point: 取った人` を書く。図の下に −N … 0 … +N の目盛りが出て、点が決まるたびに印が動く。決まる球は、そのゲームで点を取る打ち方で描き、相手の届かない所（位置の名前）に落とす。ディンクのゲームでは、決まる球を攻めのディンク（相手の届かないキッチンの角や足元に落ちるディンク）で描き、スピードアップでは描かない（書き手が決めた規則）。次の球はコードが新しいボールにする。点を失った人の上には、その手が終わったときに「失点」が出る（得点は出さない）。勝ちの点に届いた手では、コートの真ん中に「〇 の勝ち」がポンと出て、線の名前は消える。繰り返しの最初で、目盛りは一度に0へ戻る。勝ち負けが分かるように、0 から勝ちの点まで動く例を描く。
- **ミスと失敗の決まり**：球を何個も使い、「何個まで減ったら失敗して出し直す」決まりのドリル（dnk005 など）は、失敗する球に `miss: net`（受ける人へ向かって飛び、ネットで止まる。名前は「ミス（ネット）」）か `miss: out`（受ける人の外へそれて、コートの外に落ちる。名前は「ミス（アウト）」）を書く。止まった所・落ちた所に「×」と「残りNつ」が出る。ミスの名前と「×」は赤で出し、ミスの球はほかの球と同じ速さで飛ぶ。いろいろなミスを見せるため、2つ目以降のミスは種類を変える。次の手からは、その球を書かない。図に `failAt: 何個以下で失敗` を書くと、そこまで減った手で、コートの真ん中に「失敗／Nつから出し直し」が出る。最初の手は球出し（`feed: true`・`afterBounce: true`）にして、繰り返すと新しい球から始め直す（書き手と決めた 2026-11-28）。
- **打つ形を作るとき**：打つ瞬間のパドルの面の向き（横から見た図ではパドルの線に垂直な前向きの側）を、球の飛ぶ向きとそろえる（差は 25° 以内）。決めのポーズは /dev/pose/（手元だけ）で、お手本の動画のコマと、面の向きが合っているかを見てから入れる。
- **長さの単位**：ページに出す長さ（文章・図の見方・表）は cm・m で書く。フィートは使わない（読み手は日本人。書き手の指示）。データと計算は ft のままで、表示は `config/court.ts` の `metric()` で直す。
- **高さ**：打つ高さと山の高さは、打球の種類で決まる（`config/court.ts` の `heightLevels`・`shotHeights`）。受ける高さは、受けた人が次に打つ球の打点。違う高さで打つ球だけ `hit:`・`peak:` を書く（例: ロールのスピードアップは `hit: underTape`）。打つ高さが場面で変わる打ち方（`shotHeights` に `range` がある。例: リセットは腰の高さ〜足首、ワンバウンドもある）は、ドリルの場面に合う `hit:` を書く。上から投げ下ろすように、打った高さから上がらずに弧を描いて落ちる球は `fall: true`（例: dnk009 の手投げの球出し）。
- トランやベースラインに人がいる側は、自動でベースラインまで描かれる。
