# add-drill

ドリル1つ = `src/content/docs/drills/<カテゴリ>/<ID>.md` 1ファイル。本文は書かず、frontmatter の `drill:` に中身を書く。ページの表示は `src/components/DrillDetail.astro`、図は `src/components/Court.astro` が frontmatter から組み立てる。

## 手順

1. **元の情報を読む**：依頼のメニュー文やメモを読む。練習会のメニューを集めた `menus-raw/`（ローカルにだけある。なければ飛ばす）と、洗い出し一覧 `menus-raw/drill-inventory.md` があれば、同じドリルがないか、どのIDを使う予定かを確かめる。
2. **ドリルの単位を決める**（下の「ドリルの分け方」）。既存のドリルの派生形で済むなら、新しいファイルは作らない。
3. **カテゴリとIDを決める**（下の「カテゴリとID」）。同じカテゴリの最大の番号の次を使う。
4. **ファイルを書く**（下の「frontmatter の書き方」「図の書き方」）。書き方に迷ったら、近いカテゴリの既存ドリルを1つ読んで合わせる。
5. **文章を確認する**：yomiyasu スキルが使えるなら、`node scripts/extract-prose.mjs <カテゴリ/ID>` で文章を抜き出して yomiyasu にかけ、直した内容をファイルに戻す。使えないときは、短い主語や句のあとの読点（「球出し役は、」）を外す程度にとどめる。
6. **ビルドと表示を確認する**（下の「確認」）。
7. **推測で書いたところを書き手に伝える**：元の情報に書かれていなかった配置、球出しの位置、ラリーの有無、ポイントなどは、どれを推測したかを一覧にして確認してもらう。

## ドリルの分け方

- **派生形（`variants`）にするのは、打ち方だけが違うもの**：フォア/バック/ランダム、スライス/ロール、ノーバウンド/ワンバウンド、ボールの高さ（足首・腰下・高め）など。
- **配置・球出しの位置・ラリーの有無・ゲームのルールが違えば、別のドリル**にする。例：半面とクロス（全面）は別ドリル。7/11 の始め方の違いも別ドリル。
- 同じ練習の言い換え（「ストローク→ドロップ」と「ドライブ→ドロップ」など）は1つにまとめる。
- ドリル名はチームの呼び方をそのまま使う（トラン、7/11、ボレスト、スキニーシングル、ファイヤーファイトなど）。一般的な言い方に直さない。

## カテゴリとID

IDは「英数字3文字のカテゴリ + 3桁の数字」（例: `dnk001`）。カテゴリは `src/config/categories.ts` が正。

| コード | カテゴリ | 入れるもの |
|---|---|---|
| `dnk` | ディンク | ストレート/クロスのディンク、攻め/守りのディンク |
| `drp` | ドロップ | トランやベースラインからのドロップ、3rdショットドロップ |
| `rst` | リセット | 近くでのリセット、トランでのリセット、リセットラリー |
| `spd` | スピードアップ・ファイヤーファイト | スピードアップ、カウンター、ファイヤーファイト |
| `vly` | ボレー | ボレスト、ボレーボレー、ブロックボレー、攻撃的ボレー |
| `4th` | 4thショット | 相手の3rdを受ける4th（受け流す・ロール・フリック・ブロック） |
| `trn` | トランジション | 前に詰める（アプローチ）、サーブ側 vs リターン側の勝負 |
| `lob` | ロブ・スマッシュ | スマッシュ、ロブへの対応 |
| `drv` | ストローク・リターン | ストロークのフォーム、リターン |
| `ftw` | フットワーク | サイドステップなど |
| `gam` | ゲーム形式 | ディンクゲーム、7/11、スキニーシングル、キャット&マウス |

**表示順**：IDは作った順の番号、表示順（サイドバーやドリル一覧で並ぶ順）は別に持つ。すべてのドリルに frontmatter の最上位で `sidebar: { order: 番号 }` を書く（カテゴリの中で 1, 2, 3…）。新しいドリルを途中に並べたいときは、IDは最大の番号の次を使い、表示順だけを入れたい位置にして、後ろのドリルの表示順を1つずつずらす。

「アップ」はカテゴリにしない（ストレートディンクなどは `dnk` に入れる）。一度使ったIDはなるべく変えない（メニューのURLで使うため）。ただし今（2026-11 時点）は試行錯誤の段階なので、書き手の指示があれば付け替えてよい。

## frontmatter の書き方

型は `src/content.config.ts` が正。最小の例：

```yaml
---
title: トランからストレートドロップ
description: トランから相手のキッチンに落ちるドロップをストレートに打つ
sidebar:
  order: 1
drill:
  id: drp001
  category: drp
  purpose: サーブ側はベースラインからトランまで上がってきて、キッチンまであと一歩のところにいる。ここで確実にドロップを相手のキッチンに落とすのは、スマッシュや強めの球を打ち返されないままキッチンへ上がるため。
  setup: 2人1組でストレート（正面）に向かい合う。球出し役はキッチンライン付近、練習役はトランに立つ。1面で2組同時にできる。
  feed: 球出し役がキッチンから練習役のトランへ球を出す。
  steps:
    - 練習役はトランで構えて待つ
    - 来た球をストレートにドロップし、相手のキッチンに落とす
    - 一定時間で球出し役と練習役を交代する
  points:
    - ネットの少し上を通し、相手のキッチンに落とす
  diagram:
    players:
      - { id: A, x: 5, y: 14, role: feed }
      - { id: B, x: 5, y: 36.5, role: practice }
    shots:
      - { from: A, to: B, type: dink, feed: true, n: 1 }
      - { from: B, to: [5.5, 18], type: drop, n: 2 }
  variants:
    - { key: fh, name: フォア, note: フォアハンドで打つ。 }
    - { key: bh, name: バック, note: バックハンドで打つ。 }
  time: { min: 2, sets: 5 }
  related: [drp002]
---
```

- `setup`（人数・配置）、`feed`（球出し）、`steps`（やり方）、`points`（ポイント、最大3つ）は、練習中にスマホで見る項目。短く、具体的に書く。
- `purpose`（目的）は図のすぐ下に出る。練習中にいちばん意識してほしいことを書く。「〜できるようにする」ではなく、**なぜその球が必要か**（試合のどの場面で、打てると何が起きるか、そのドリルならではの理由）を書く。目的なので「〜なれる」ではなく「〜するのは、〜になるため」の形で結ぶ。「キッチンへ上がると相手と対等になる」のような、どのドリルにも共通する前提は目的に書かない（「大原則」ページ `src/content/docs/principles.md` にまとめる）。例（drp001）: 「サーブ側はベースラインからトランまで上がってきて、キッチンまであと一歩のところにいる。ここで確実にドロップを相手のキッチンに落とすのは、スマッシュや強めの球を打ち返されないままキッチンへ上がるため。」
- `variants`、`time`（標準時間）、`related`（関連ドリルのID）、`notes`（補足）は「詳細」に隠れる項目。
- 文体は「〜する」の常体。役割は「球出し役」「練習役」「相手役」、人は図と同じ A・B で呼ぶ。
- `time` は元のメニューに書かれた「1セットの分数 × セット数」をそのまま使う。

## 図の書き方

座標はフィート。コートは縦向きで x: 0〜20（左→右）、y: 0〜44（上のベースライン→下のベースライン）。ネットは y=22、キッチンラインは y=15 と y=29。**下側が自分たちの側（練習役の側）**。

- **立ち位置の目安**：キッチンライン付近は上 y=14 / 下 y=30。**トランはキッチンラインとベースラインの中間**で上 y=7.5 / 下 y=36.5。**サーブ・リターン・3rdショットを打つ人はベースラインの後ろ**で上 y=-2.5 / 下 y=46.5（ベースラインの上や内側に置かない）。トランは位置（線）の考え方で、エリアとして塗らない。
- **ドロップの的（柵）**：ドロップ系の練習は、相手のキッチンに柵をL字に置き、柵に当てずに柵の内側へ落とす。柵はサイドラインから40cm・キッチンラインからパドル1本分（どちらも約1.3ft）。上側の左なら `fences: [[[1.3, 16.3], [8, 16.3]], [[1.3, 16.3], [1.3, 21.5]]]`、着地点は柵の内側 `[3.5, 18.5]`。クロスドロップは柵の角をねらうので、角のすぐ内側 `[2.3, 17.3]`。
- **コートの使い方**：ストレートは同じ x（例: 5 と 5）、クロスは対角（例: 5 と 15）。半面は左半分（x: 0〜10）の中に置き、`zones: [left]` で示す。
- **人**：`role` は `feed`（球出し役）/ `practice`（練習役）/ `partner`（味方）/ `opponent`（相手）。全員右利きとして自動で腕とパドルを描く。構えを変えるときだけ `paddle: fh | bh` を付ける。
- **打球**：`type` は `dink` `drop` `reset` `drive` `volley` `speedup` `lob` `smash` `serve` `return`、人の動きは `move`。線の形・太さ・弧・アニメーションの速さは種類で自動で決まる（`src/config/court.ts`、「図の見方」ページ）。
- **球出しは球種ではない**：球出しの球は、出す球の種類を `type` に書き、`feed: true` を付ける（名前は「球出し（ディンク）」になる）。
- **順番 `n`**：打つ順に 1, 2, 3… と付ける。番号ごとに1コマになり、アニメーションで1手ずつ再生される。同じ番号の線は同時に動く。
- **人が動く**：`{ from: B, to: [x, y], type: move, n: 2 }` で動かすと、次の手からは動いた先に描かれる。動いた先から打つ線は、`from` にその座標を書く（2回目以降の移動は `from: B` のままでよい）。
- **相手に向かう球**は `to` に人のID（パドルに向かう）、**コートに落とす球**は `to` に座標を書く。
- `curve` は書かない（弧は種類で決まる）。`label` は名前を変えたいときだけ。
- **バウンド**：アニメーションでは、ボールは線の上（パドルの位置）を進み、高さは図の右の淡い帯「横から見た高さ」（補助の図。人とパドルの高さも出る）に出る。帯のボールが地面の線に触れたところでバウンドし、コートの図に黄色い輪が出る。
  - `to` が座標の球（コートに落とす球）は、終点でバウンドする。途中で人が取る（ノーバウンド）なら `bounce: false`。
  - サーブ・リターンは、相手の手前で自動でバウンドする。位置が大事なら `bounce: [x, y]` で書く。
  - それ以外で相手に向かう球（`to` が人）はノーバウンド。バウンドしてから打つ球（ディンクの打ち合い、トランへの球出しなど）は `bounce: [x, y]` を書く。
- **高さ**：打つ高さと山の高さは、打球の種類で決まる（`config/court.ts` の `heightLevels`・`shotHeights`）。受ける高さは、受けた人が次に打つ球の打点。違う高さで打つ球だけ `hit:`・`peak:` を書く（例: ロールのスピードアップは `hit: underTape`）。
- トランやベースラインに人がいる側は、自動でベースラインまで描かれる。

## 確認

```sh
nvm use                          # Node 24（.nvmrc）
npm run build                    # 型のエラー（frontmatter の書き間違い）はここで出る
npx astro dev --background       # 開発サーバー（http://localhost:4321/pickleball-drills/）
```

- 型や設定（`content.config.ts`、`config/court.ts`）を変えたあとは、開発サーバーを `npx astro dev stop` してから起動し直す。古いデータが残るときは `node_modules/.astro` を消して `--force` を付ける。
- ブラウザでドリルのページを開き、スマホの幅（400px 前後）で次を確かめる：
  - アニメーションで、線とボールが正しい人のパドルから出て、正しい相手（パドル）や場所に向かうか
  - 線の名前が人やネットに重ならず、図からはみ出していないか
  - タイトル・アニメーション・操作ボタンが1画面に収まるか
