  - やめた案：影をボールの下にずらす（離すと不自然、寄せると高さが分からない）。
  - やめた案：3D表示（位置が読みにくく、スマホでは奥が小さすぎた）。
- アニメーションでは各手の終わりにボールを消さず、届いた位置に残す。
- ドロップ系の練習に柵を置き、クロスは柵の角をねらう。
  - やめた案：赤い太線の柵（打球の線に見え、目立ちすぎた）。
- 目的は「詳細」に隠さず、図のすぐ下に出す。目的を意識するかどうかで練習の質が変わるため。
- 目的には「なぜ」を書き、共通の前提は「大原則」ページにまとめる。
- IDと表示順を分ける。IDは作った順、表示順は各ドリルの `sidebar.order` で持つ。今は試行錯誤の段階なので、IDは付け替えてよい。
- メニュー表示を作った（トップページと兼用）。メニューはURLだけで表す。
  - 形式：`/?v=1&theme=テーマ&total=120&m=h:見出し,drp001.fh:2x5,b:5,x60:本文`。クエリの名前は全部小文字にし、大文字・小文字の違いで区別しない（読むときも区別しない）。
  - 自由記述には分数を任意で付けられ、合計の時間に入る。
  - 行をタップしたときに、そのドリルの中身（`/fragments/ドリルID/`）を読み込んで差し込む。全ドリルの図を最初から読み込むと重いため。
  - 形式の読み書きは `src/lib/menu.ts`、ドリルの一覧データは `/drills.json`。
- ビルダー（`/builder/`、PC向け）を作った。画面の部品は Preact で作り（`src/components/builder/Builder.tsx`）、ほかのページには使わない。
  - 左でカテゴリと名前からドリルを探して足し、右でメニューを組む。見出し・休憩・自由記述を足せる。並べ替えはドラッグか ↑↓。
  - 練習全体の時間を入れると、残りと超過を出す。
  - URLのコピー、チャット用の文章（URL付き）のコピー、プレビューができる。前に作ったメニューのURLを貼って読み込める。
  - 保存の機能は持たず、作業中の内容だけをブラウザに残す。
  - 入口は、トップページの一番下の「メニューを作る」と、メニュー表示の一番下の「このメニューを編集」の2か所だけ（どちらも小さな灰色の文字）。
- ドリルには「ビルダーの初期値」（`builderDefault`：何分×何セット）だけを持たせ、ドリルのページには出さない。その日の実際の時間はメニューのURLが持つ。前の「標準時間」は、メニューと違う値が見えてまぎらわしかったため表示をやめた。
- ビルダーの見た目のために、Tailwind CSS と daisyUI は入れない。状態を持つ画面がビルダー1つだけで、daisyUI はサイト全体に読み込まれ、テーマの切り替え（`data-theme`）が Starlight とぶつかる恐れがあり、メンバーが見るページを崩しかねないため。代わりに、ビルダーをサイトの枠（Starlight、サイドバーなし）の中に置き、色を Starlight の変数に合わせた。
  - 見直す目安：状態を持つ画面が増えたとき（メンバー向けの入力画面など）。そのときも、まず Starlight が公式に対応する Tailwind だけを入れ、daisyUI は部品が足りなくなってから考える。
- コートは、ライトでもダークでも、実物のように濃い緑の面に白い線で描く。ライトで淡い緑に白い線だと、線や文字が見えにくかったため。横から見た高さの帯だけは、ページの背景の上に描くので、線の色をライトとダークで変える。
- 打球の線をピンクから水色に変えた。コートを濃い緑にしたあと、ピンクはコートとの明るさの差が小さく、浮いて見えるのに見えにくかったため（ピンクは、もとは黄色いボールと見分けるために選んだ）。合わせて、味方を水色と紛れない薄い紫に、柵を球出し役のオレンジと紛れないくすんだベージュにした。色の決まりは「ボールは黄色」だけ。
- 図で色を使うのはボール（黄色）と打球（水色）だけにした。人は役ごとの色をやめ、練習役（自分）だけ白い丸、ほかは濃い丸にし、役は A・B と図の下の文字で伝える。柵も灰色にした。「色で見分ける必要があるか」から考え直した結果で、役ごとの色は凡例を見ないと意味が分からず、ライトのコートでは練習役の青がほとんど見えなかった（明るさの差 1.2）。
- 上から見た図の打球の線を、弧からまっすぐに変えた。弧は高さの代わりだったが、横から見た帯で高さを見せるようになり、弧は「横に曲がって飛ぶ」ように見える恐れがあったため。柔らかい球かどうかは、線の形（点線・破線・太さ）とアニメーションの速さで伝える。
  - やめた案：打球を点の並び（間隔＝速さ、大きさ＝高さ）や短い線の並び（長さ＝速さ、太さ＝高さ）で描く。並べて見比べた結果、今の線（実線・点線・破線と太さで球の種類を分ける）のほうが分かりやすかった。
- ドライブ（ストローク）の高さを、トップスピンの軌道（前半はゆるやかに上がり、ネットの手前で山、越えたあと加速して沈む）にした。打点は「腰の下」に変えた（ベースラインから打つ球のため）。
- アニメーションの速さを、種類ごとの固定の時間から「距離 ÷ 種類ごとの速さ」に変えた。前は同じ種類でも遠い球ほど速く見えていた。
- ドリルのデータに座標を直接書くのをやめ、名前で書くようにした（立ち位置 `at: near-right-baseline`、柵 `fence: far-left`、着地点 `fence.corner` / `fence.inside`）。座標の決まりは `src/config/court.ts` の1か所にあり、データを読み込むときに座標に直す。ルールが説明文や Claude の頭の中ではなく、コードにある状態にするため。
  - バウンド位置も決まりにした（`bounce: front` = 受ける人の手前で弾む。ベースラインの後ろで受ける球は4.3ft、それ以外は2.1ft手前。サーブ・リターンの既定も同じ）。データに書いていた座標の位置とは1ft以内で一致。`4th005` のリターンは、前は相手のかなり手前で弾んでいたのが、深いところで弾むようになった。
- ボレーを4種類に分けた：受け流しボレー（ネットより下で当て、弧を描いてゆっくり落ちる。ディンクを受けるときもドロップを受けるときも同じ）、ブロックボレー、ロールボレー、パンチボレー。種類ごとに高さ・速さ・線の形が変わる。4th は受け流し、ファイヤーファイト（spd）はパンチ、drp006 と lob003 はブロックにした。
  - 「受け流しボレー」の名前を、一般的な呼び方の「ボレーディンク」（volley dink）に変えた。メンバーが動画などで調べやすいため。ドロップをノーバウンドで受け流すときも同じ名前で描く。
- 高さの段階に「膝の高さ」（1.3ft）を足し、ディンクの打点にした。前は「白帯のちょい下」で、ディンクの打点が高すぎた。
