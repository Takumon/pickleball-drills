# コート図とアニメーションの約束

値（色、線の太さ、高さの段階など）は `src/config/court.ts` にある。ここには、なぜそう描くかを書く。

## 視点と人

- コートを真上から見た図にし、下側を自分たち（練習役）の側にする。自分の側から相手を見る向きが練習中の感覚に合うため。
- 人は全員右利きとして描き、特に断りがなければフォア側で打つ練習として描く。
- 腕は細い線、パドルは太い線で、体から斜め前に開くように描く。
- サーブ・リターン・3rdショットを打つ人は、ベースラインの後ろに置く。実際にそこから打つため。
- トランは「エリア」ではなく、キッチンラインとベースラインの中間の「位置」として扱う。トランに人がいる図は、位置関係が分かるようにベースラインまで描く。

## 打球の線

- コートは、ライトでもダークでも濃い緑の面に白い線で描く（実物のコートに近く、白い線や黄色のボールが見やすい）。
- コートの外まわり（ベースラインの後ろなど）も、少し濃い緑の地面として塗る。人がコートの外に立っても、ページの背景に溶けないようにするため（ライトでは白い丸の練習役が見えなくなった）。
- 色を使うのは、図の主役の「ボール」と「打球」だけにする。ボールは黄色で、穴のあいたピックルボールとして描く（実物のボールの色。ここだけは変えない）。打球の線は水色。水色は、濃い緑のコート、白い線、黄色のボールのどれとも見分けやすい。
- 人には色を付けない。練習役（自分）だけ白い二重丸（丸の内側に線を入れる）にし、ほかの人は濃い丸にして、「誰のための練習か」が一目で分かるようにする。2人とも練習するときは2人とも二重丸にする。外側に輪を足すと、人が大きく見えるため内側にした。図の下に役の一覧（凡例）は出さない。行を取るわりに、図だけで分かることしか書いていないため。役ごとに色を変えると、見る人が色の意味を覚える必要があり、主役の打球が目立たなくなるため。
- 上から見た図の打球の線はまっすぐに描く（真上から見るとボールの通り道はほぼまっすぐ。高さは横から見た帯で見せる）。線の太さ・形・アニメーションの速さは打球の種類で変える。速く強い球は太い実線、柔らかく落とす球は細い点線、ロブは破線にする。
- 線の名前（ドロップ、ボレーなど）は線の上に書く。色の凡例で説明すると、図と凡例を見比べる手間がかかるため。
- IDやカテゴリのようなメタ情報はページに出さない（データとしては持つ）。

## アニメーション

- ボールが飛ぶ時間は、距離 ÷ 球の種類ごとの速さ（実際の球速の目安、`config/court.ts` の `shotSpeedKmh`）で決める。同じ種類の球は距離によらず同じ速さに見える。目で追えるよう、全体を同じ割合でゆっくり再生する（`ANIM_SLOWDOWN`）。1手は0.4〜2秒に収める。
- 手が2つ以上ある図は、アニメーションだけで見せる。コマ割りで並べると、スマホでは1コマが小さくなりすぎるため。
- 各手の終わりに、ボールは届いた位置（受ける人のパドル、または着地点）に残し、次の手はそこから始める。ボールの受け渡しのつながりを見せるため。
- **連続性（つながり）を必ず守る**。前の手の終わりと次の手の始まり、最後の手から最初の手へ戻るところで、人の位置、ボールの位置（上から見た図）、ボールの高さ（横から見た図）が、どれも途切れたり跳んだりしないようにする。手を足すとき・直すときは、書き手に言われなくても確かめる。全部のドリルを `.claude/skills/add-drill/anim-check.js` でまとめて測る（つながり、打つ瞬間に面が球に当たっているか、面の向きが球の飛ぶ向きと 25° 以内か）。
  - 人が動く手は、動いた先が次の手で描かれる位置と一致する（線の長さではなく、体の中心の差だけ動かす）。
  - 繰り返したときに跳ばないよう、最後の手のあとの立ち位置を最初の手の立ち位置にそろえる（例: クロスディンクのラリーは、A が外側で受けたところから始める）。
  - トラップや手から落とす球は、前の手で球が届いたパドルの位置と高さから始める（トラップは受けた高さから少し上がって落ち、パドルの真下で弾む）。
  - 例外: ゲーム形式の点の目盛りは、繰り返しの最初で一度に0へ戻す（流れて戻ると、点が動いたように見えるため。書き手の判断）。
- 球を2つ以上同時に使う手は、どの球もボールと横から見た図の通り道を描き、同時に飛ばす。同じ手で2本の線がほぼ同じ所を通るとき（ストレートの往復など）は、重なって読めないので、どちらの線も進む向きの右へ少しずらす（両端はパドルのまま）。
- 打つ動き（全部のアニメーションに共通。court-anim.ts）: 相手の球が飛んでくる間に振りかぶり、打つ手で振りかぶり → 打つ所 → 振り抜きと振り、振り抜いた形で少し止まってから構えに戻る。ボールはパドルが打つ所を通る瞬間に飛び出す。横から見た図では、パドルの向きも振りに合わせて回り、腕は長さを変えずに曲げ直す。
- 手と手の間は 0.7秒（1手ずつ区切ると、誰が何を打ったかを読み取りやすい）。ただし、次の手がトラップ（受けた球を面でポンと上げてから打つ）で始まるときは、受けた球の続きの動きなので間を入れない。どちらにするかはコードが手ごとに決め、ドリルのデータには書かない。1周が終わったあとは 1.6秒止まる。
- コートの図のボールは打つ人と受ける人のパドルの位置を通る。
- 「視差効果を減らす」設定の端末では自動で再生せず、手を1つずつ切り替えて見せる。

## 横から見た図の人

- 人は「関節の点をつないだ骨組み」に「部分ごとの太さ」を付けて描く（src/lib/side-figure.ts）。寸法は身長 170cm の大人の比率（Drillis & Contini）、構えはピックルボールのよい姿勢（上体はほぼ起こし、ひざを少し曲げ、パドルは体の前）。
- 低い球でも前かがみやしゃがみ込みにはせず、ひざと上体の傾きは決まった範囲で深くし、届かない分は腕を伸ばす。
- パドルの面の真ん中は、ボールと同じ高さ・奥行きに置く。
- 人・ネット・パドルは実物の比率で描き、ボールだけは見やすさのために実物より大きく描く（実物の大きさではスマホで1ピクセル前後になり、追えないため。横から見た図で約3.5倍、上から見た図で約5〜8倍）。
- パドルの向きは打つ高さで決める: 腰より下では腕の延長でヘッドが下がり、腰より上では高くなるほどヘッドが上を向く。
- 打つ動きは打球の種類ごとに決める（config/court.ts の shotSwing）。一覧は「図の見方」に出す。振りかぶりから打つ所までに途中の点（via）を置ける。手は点から点へ、肩を中心にした弧で動く。
- 横から見た図の構え: ひざを曲げて腰を落とし、胸はほぼ起こす。ひじは体の少し前、手は体の前。打ち方ごとの構えは lib/side-figure.ts の STANCE_BY_SHOT（決めのポーズがある打ち方は keyPoses）。受ける人は次に打つ球の構えで描く。打つ瞬間の面の向きは球の飛ぶ向きとそろえる。
- 腕と手だけ肌の色にする（パドルの大きさと見比べるため。色の決まりの例外）。パドルは縁から見た細い形で描く。
- パドルは、上から見た図と横から見た図の両方でローズにする（2つの図を結び付けるため。色の決まりの例外はここまで）。
- 横から見た図は補助の情報なので、全体を控えめにする。人も控えめに描き、足や靴との見分けは、地面の線を人よりさらに薄く細くしてつける。

## 高さとバウンド

- 高さは図の右に添えた淡い帯「横から見た高さ」で見せる。同じ場面を横から見た図で、縦の位置はコートとそろえ、右ほど高い。人とパドルの高さも描く。
- 帯は補助の情報なので、細く淡く描き、主役のコートの図と見た目で差をつける。
- 帯は補助の情報なのでシンプルにする。地面は1色の線で、ベースラインとキッチンラインの位置は、同じ太さのまま、その部分だけ地面の線より薄い色にして示す（切れ目にすると地面に穴があいたように見えた）。柵は帯には描かず、コートの図だけで示す。柵は描かない（補助の図には要らない。柵はコートの図だけで示す）。コートの色の帯や、色分けした地面の線は試したが、補助の図としては情報が多すぎたのでやめた。
- 高さは13段階（地面、膝の高さ、腰の下、白帯のちょい下、ネットの白帯、白帯のちょい上、白帯の約30cm上、腰上〜肩下、肩より上・頭付近、白帯から上、頭より上、頭のかなり上、かなり上）で決める。打つ高さと山の高さは打球の種類で決め、受ける高さは受けた人が次に打つ球の打点にする。
- ディンクの仲間（ディンク、スライスディンク、ボレーディンクと、それぞれのトラップ）とリセットは、打つ人の側で山（白帯の約30cm上）になり、ネットの白帯の約20cm上を通って、ネットを越えたら下がっていくように描く。ネットぎりぎりを通すとネットにかけやすく、大事なのは相手が打つところで低いことだから（書き手の指摘）。受ける人のところでも低く、次に打つ球が図にないときは腰の下（弾んでから受けるなら膝の高さ）で受ける。
- ドライブ（ストローク）は、腰の下から低く打ち出して少しだけ弧を描き、ネットの手前で山になって白帯を越え、トップスピンでネットを越えたあとにぐっと沈むように高さを描く。
- ボールが弾む位置には黄色い輪を出す。横から見た高さの帯でも、同じ瞬間に地面の線の上に同じ輪を出す。2つの図が同じバウンドを表していると分かるようにするため（2つの輪を点線で結ぶ案は、なくても分かるのでやめた）。輪のない球はノーバウンドで打つ。ノーバウンドで取るかどうかが、ドリルの中身を左右するため。

## 柵

- ドロップ系の練習では相手のキッチンにL字の柵を置き、柵に当てずに内側へ落とす。柵はサイドラインから40cm、キッチンラインからパドル1本分の位置に置く。
- クロスのドロップは柵の角をねらう。
- 柵は補助のものなので、灰色の細い横木と支柱で描く。支柱の形で、打球の線やコートの線と見分ける。

## 見やすさの確かめ方

色を変えたら、ライトとダークの両方で、背景との明るさの差（コントラスト比）を計算して確かめる。
- コートの上の主なもの（線、打球、ボール、文字、人、柵）は、コートの面に対して 3 以上にする。
- 横から見た帯の地面の線や文字も、帯の下地に対して 3 以上にする。
- ラインの位置のように、わざと薄くする印でも 2 前後は残し、消えて見えないようにする。


- 打つ動きの形は打ち方ごとに「決めのポーズ」（構え・引き切り・打つ瞬間・振り抜きの関節の角度。config/court.ts の keyPoses）で決め、そのあいだを動かす。ポーズはお手本の動画のコマと並べて書き手が確かめてから入れる（/dev/pose/。手元だけ）。まだ決めのポーズがない打ち方は、手の位置の振り（shotSwing）で動かす。
