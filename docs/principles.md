# サイトの目的と方針

## 目的

ピックルボールの練習会で使う練習メニューと、メニューに出てくるドリル（練習1つ分）を公開する。

## 読者

書き手と決めた（2026-11-28）。

- **A. 当日の練習会の参加者**：書き手が組んだ練習メニューの URL を開き、メニューのページに直接着く。体育館やコートで、練習中にスマホで見る。
- **B. サークルのメンバー**：書き手がサークルの中で周知した URL から、「どんなものか」を見に来る。サークルで質の高い練習をしたい人たち。練習の前後に、自宅でじっくり見ることもある。
- **C. サークルの外の人**：共有された画像やリンクから来る。このサークルが練習を大事にしていることを、まだ知らない。サイトを見て、サークルに魅力を感じてもらいたい。
- **D. 書き手（メニューを組む人）**：PCでドリルを選び、練習メニューを組む。

いちばん大事にするのは、練習中にスマホで数秒見て分かることである（A）。

トップページは B と C のためのページにする（A はメニューのページに、D はメニューを作るページに直接行くため）。B には、自分たちの練習がたくさん、分かりやすく整理されていて、予習・復習に使えることを伝える。C には、運営するサークルが練習の中身をよく考えていることを伝え、サークルのページへ進めるようにする。どちらにも「練習がたくさんあって、図が動くから分かりやすそう」という印象を最初に持ってもらう。

## 見せ方の方針

- 日本語だけで作る。
- タイトルとアニメーションが、スマホの1画面に収まるようにする。
- 最初から見せるのは、図と、想定する試合の場面、その場面でやりたいこと、練習の目的、練習のコツだけにする。人数・配置、球出し、やり方はアニメーションで伝わるので「練習方法の詳細」に折りたたむ。練習中にスマホで長い文は読まないため。ID・カテゴリ・別名・メニューの初期値は作り手だけが使う情報なので、データとして持つが表示しない。
- 練習会の日付・会場はサイトに出さない。
- 作り手向けの画面（メニューを作る画面など）へのリンクは目立たせない。メンバーが迷わないようにするため。

## 文章の方針

- ドリル名はチームでの呼び方（トラン、7/11、ファイヤーファイトなど）をそのまま使い、用語集で説明する。
- 目的には「〜できるようにする」ではなく、なぜその球が必要かを書く。試合のどの場面で、その球を打つと何が起きるかを書き、「〜するのは、〜ため」で結ぶ。
- 「キッチンに上がると相手と対等になる」のような、どのドリルにも共通する前提は目的に書かず、サイトの「大原則」ページにまとめる。
- 文章は常体（〜する）で書く。新しく書いた日本語は yomiyasu スキルで確かめてから反映する。

## 作り方の方針

- 少しずつ作って見せる。一度にたくさん作ると、同じ指摘を何度も直すことになるため。ドリルは数カテゴリずつ下書きして確認してもらう。
- 書き手は公開されたページ（GitHub Pages）をスマホで見て確認することが多い。プッシュする前に、ローカルの開発サーバーとブラウザで、指示どおりに直っているかをスマホの幅でも確かめる。
- 不明な点は1つずつ番号を振り、おすすめを添えて文章で聞く。

## 公開しない情報

リポジトリもサイトも公開されている。次のものは git に入れない（コード、このフォルダ、コミットのメッセージを含む）。

- 個人を特定できる情報（名前、アカウント名、メールアドレス）
- 練習会の団体名、日付、会場、参加者
- 外部のサービスから集めた練習会の情報（メニューの本文、イベントやチャットのID、集め方）

これらは git の管理から外したローカルのフォルダ（`menus-raw/`）にだけ置く。ドリル名や練習の中身は、サイトで公開するためのものなので書いてよい。ただし、どの練習会のメニューから来たかは書かない。
